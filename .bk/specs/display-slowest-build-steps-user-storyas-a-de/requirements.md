## User Stories

### Create Slowest Builds Table Component
- **Story:** As a DevOps engineer, I want to see a table of slow build steps so that I can quickly identify performance bottlenecks
- **Priority:** P1
- **Story Points:** 5
- **Acceptance Criteria:**
  - [ ] Table displays workflow name, job name, step name and duration
  - [ ] Table is sortable by duration column
  - [ ] Table shows top 20 rows by default
  - [ ] Each row links to the corresponding workflow run
  - [ ] Table updates when new data is received

### Implement Build Step Service
- **Story:** As a developer, I want a service to fetch and filter slow build steps so that I can provide data to the UI efficiently
- **Priority:** P1
- **Story Points:** 3
- **Acceptance Criteria:**
  - [ ] Service fetches build step data from API
  - [ ] Filters steps under 30 seconds duration
  - [ ] Limits results to specified number of rows
  - [ ] Handles API errors gracefully
  - [ ] Implements caching for performance

### Create Build Step Data Model
- **Story:** As a developer, I want a data model for build steps so that I can consistently structure build step information
- **Priority:** P1
- **Story Points:** 2
- **Acceptance Criteria:**
  - [ ] Model includes workflow name, job name, step name fields
  - [ ] Model includes duration in seconds
  - [ ] Model includes workflow run ID for linking
  - [ ] Model includes created/updated timestamps
  - [ ] Model implements proper validation

### Implement Slowest Steps API Endpoint
- **Story:** As a developer, I want an API endpoint for slowest build steps so that I can retrieve filtered build step data
- **Priority:** P1
- **Story Points:** 3
- **Acceptance Criteria:**
  - [ ] GET /api/build-steps/slowest endpoint implemented
  - [ ] Accepts limit parameter with default of 20
  - [ ] Accepts min_duration parameter with default of 30
  - [ ] Returns properly formatted JSON response
  - [ ] Includes proper error handling
